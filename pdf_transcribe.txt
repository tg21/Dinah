DND: A Multi-Agent System for System Creator

An application that works on top of existing harnesses. It should be Harness or LLM provider agnostic as much as possible.

We have agents that we need for a Software Engineering Company.

Detailed Agent Roles & Responsibilities

1. CEO Warlock

Main entry point of the application.

Anything new comes to the CEO first.

He will delegate work downstream.

Only new project requests will go through the CEO.

2. HR Mind Flayer / Illithid

After receiving new work, the CEO will ask HR for a Manager.

The HR agent is responsible for any new agents.

Initial State: Initially, we will only have the CEO and HR.

[IMPORTANT REQUIREMENT]: ONLY HR can spawn new agents.

HR takes the required template from the templates folder and spawns a new agent.

For a new project, HR will spawn a Manager Agent.

Later, HR will spawn any agent that the Manager agent requests.

HR System Maintainer: HR maintains the HR System (a json file containing the name, role, project, and Id of every agent).

3. Manager Bard (Router Agent)

Anything related to an existing project that already has a manager will go through the Manager.

Based on requests, the Manager will request more agents from HR and delegate work to them.

4. Solution Architect Wizard

Handles architectural design, system design, and technical planning (etc. etc.).

Shared Project State: There will be a shared state for each project clearly indicating what each agent is working on.

HR System Registry (json):

Contains name, role, project, and Id of every agent.

Managed exclusively by the HR agent.

Inter-Agent Communication:

Using details in the HR system, agents can talk to each other directly.

Pass each other useful information.

Ask for help with missing information or context.

Marshall Agents & System Health Checks

The system spawns Marshall Agents every 5 minutes.

                         ┌───────────────────────┐
                         │    Marshall Agent     │
                         │  (Runs every 5 min)   │
                         └───────────┬───────────┘
                                     │
           ┌─────────────────────────┼─────────────────────────┐
           ▼                         ▼                         ▼
 ┌───────────────────┐     ┌───────────────────┐     ┌───────────────────┐
 │ Check Obsolete    │     │ Context Exhaustion│     │ Stuck / Frozen    │
 │     Agents        │     │      Check        │     │     Processes     │
 └─────────┬─────────┘     └─────────┬─────────┘     └─────────┬─────────┘
           │                         │                         │
 Inform HR & clean up    Trigger handover to new   No progress (10 min) /
 obsolete agent data     process seamlessly        long shell task ->
                                                   Notify Manager / Human


Obsolete Agent Cleanup:

Inform HR of any obsolete agents and their data in the HR system.

HR can then remove them from the HR system after making sure they are actually done.

Context Window Management:

Check all agents to see if they are going to run out of context.

If yes, notify the Manager and HR to spawn a new process and execute a clean handover without losing useful context.

Stuck Process Detection & Human-in-the-Loop:

Check if any agent is stuck on long-running shell tasks or hasn't made progress in the last 10 minutes.

If so, let the Manager know. The Manager can inform the user if more context or intervention is needed to decide what to do with them (Human-in-the-Loop).

UI Features & Interactions

Top Navigation / Project Bar:

Project tabs (Project 1, Project 2, Project 3).

Header indicating active chat focus (e.g., Chat with Manager).

Play Area (Infinite Canvas):

Shows animated D&D-based agents working in real-time.

Interactive Avatar: Clicking on any agent's avatar in the play area opens that specific agent's Chat and Info Drawer.

Chat & Info Panel (Right Drawer / Side Area):

Tab 1: Chat – Direct messaging/interaction with the selected agent.

Tab 2: Agent Details & Stats – Stats styled like D&D / Baldur's Gate (BG3) character sheets.

Tab 3: Thought Process – Real-time stream of what thought process/reasoning the agent is going through.

Tab 4: Personal Context – Visualized internal context and memory state of the agent.

Tab 5: Relationships – Network graph showing who the agent has interacted with and the interaction volume.

Input Box: + Type... text entry at the bottom of the chat area.
